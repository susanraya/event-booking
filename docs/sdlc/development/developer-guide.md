<!-- sdlc:auto:start overview -->
Event booking is a two-app repository generated by the Quorq AI SDLC platform: an Angular 22 (Analog/Vite) frontend containing the approved, reviewed screens for browsing events, selecting seats and booking, currently running on seeded sample data; and a Spring Boot 4.1 (Java 21, Maven) backend that at this point only exposes a health check, with PostgreSQL 16 as the approved database for when real endpoints are added. The frontend and backend are independent apps in one repo, connected by a small typed API client that is not yet wired into any screen.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm, Vite, Angular 22 tooling)
- Java 21 (for the Spring Boot backend)
- Maven (the bundled `mvnw`/`mvnw.cmd` wrapper, no separate install needed)
- Docker and Docker Compose (to run the PostgreSQL 16 database via docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. git clone the repository and cd into it
2. cd frontend && npm install
3. (optional, for a real Postgres DB) from the repo root run: docker compose up -d
4. cd backend; no install step is needed, the Maven wrapper (mvnw) downloads dependencies on first run
5. Run the frontend with `npm run dev` (from frontend/) and the backend with `sh mvnw spring-boot:run` (from backend/)
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend: one Angular component per approved screen under src/screens/, each extending the base in src/lib/screen-base.ts (provides navigate/brand)
- Frontend: component tests sit beside the component they cover, named x.component.spec.ts next to x.component.ts, run with Vitest/TestBed
- Frontend: shared directives/components/icons live in src/lib/ui.ts and src/lib/icons.ts; brand tokens in src/lib/brand.ts and index.css
- Frontend: all backend access goes through the single apiFetch helper in src/lib/api.ts, which injects the Authorization bearer and base URL; screens currently still render seeded data rather than calling it
- Frontend uses Angular's zoneless change detection (provideZonelessChangeDetection in main.ts)
- Backend: Java package app.* with Spring Boot starter conventions; style enforced via Spotless (Google Java Format) and Checkstyle
- Backend: JPA schema managed by Hibernate ddl-auto=update as a placeholder (no Flyway migrations yet)
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails to start or create tables | hibernate.hbm2ddl.halt_on_error is enabled, so a schema mismatch stops the app; check application.properties and entity mappings, or ensure DATABASE_URL points at a reachable Postgres instance |
| No DATABASE_URL configured | The backend falls back to an in-memory H2 database automatically; run `docker compose up -d` to start the PostgreSQL 16 service defined in docker-compose.yml for a persistent DB |
| `npm run test:e2e` fails because no browser is installed | Run `npm run test:e2e:install` once to fetch Chromium before running Playwright tests |
| Frontend `tsc`/typecheck fails on `import.meta.env` | Ensure the vite/client types reference at the top of src/lib/api.ts is intact; it's needed because this module can be tree-shaken out of the build but still type-checked |
| Port 8000 or 4173 already in use when running e2e locally | Stop other processes on those ports, or set E2E_BASE_URL to point Playwright at an already-running deployment instead of booting local servers |
